# seQ: the serving-deployment language, and how this repository uses it

seQ is the language in which a serving deployment is a program: memory
pools and stages, a workload, and the route every session takes. Since
2026-09-27 it is its own project, https://github.com/vrvrv/seQ (private).
seQ holds the Rust interpreter and CLI (crate `seq-lang`, library `seq`,
binary `seq-lang`), the example programs (`programs/*.seq`, incl. the vLLM
v1 engine and its A100 replay), the vLLM scheduler oracle with its test
vectors (`tools/oracle/`, the A100 engine's answers), the language spec
(`docs/language.md`) and the review and tooling survey (`docs/review.md`).

This repository keeps the Lean model of the language and uses one pinned
seQ release:

| Here | What it is | What it takes from seQ |
|---|---|---|
| `lean/ServingQueueTheory/Seq.lean` | syntax `Route Env V` of the route block, pool semantics and invariant, surface syntax | |
| `lean/ServingQueueTheory/SeqExec.lean` | executable semantics (ℕ, step clock) | |
| `lean/ServingQueueTheory/SeqOracle.lean` | the vLLM scenarios as theorems, GENERATED by `scripts/gen_seq_oracle.py` | `tools/oracle/` of the pinned release (`make lean` checks it is current) |
| `lean/ServingQueueTheory/SeqServe.lean` | serving order of a step engine, cited in §2.2 | |
| `lean/ServingQueueTheory/Deployments.lean` | the paper's two replicas as seQ programs | |
| `libqueuingsim/tests/seq_*.rs` | seQ programs against the hand-written models and closed forms | the crate (`seq = { package = "seq-lang", git = …, tag = … }`) |
| `scripts/exp/*seq*`, `diff_seq_vllm.sh`, `first_divergence.sh` | testbed comparisons and calibration | `.seq/bin/seq-lang`, `.seq/src/programs`, `.seq/src/tools` |

The pin is the `tag` in `libqueuingsim/Cargo.toml`. `scripts/fetch_seq.sh`
(`make seq`, first step of `make check`) checks that tag out into
`.seq/src` and installs its CLI into `.seq/bin/seq-lang` (gitignored).

## Moving to a new seQ release

1. In seQ: bump `version` in `Cargo.toml`, push, then
   `git tag vX.Y.Z-devN && git push origin vX.Y.Z-devN` (or `vX.Y.Z`).
   The release workflow runs the checks and publishes the GitHub release
   (a tag with a dash is a prerelease).
2. Here: change the tag in `libqueuingsim/Cargo.toml`, run
   `cd libqueuingsim && cargo update -p seq-lang`, then `make check`. If
   the oracle vectors changed, `python3 scripts/gen_seq_oracle.py`
   regenerates `SeqOracle.lean`.

## Access

seQ is private. Locally, git and Cargo (`.cargo/config.toml`:
`git-fetch-with-cli`) authenticate through the `gh` credential helper of
an account that can read seQ. CI uses a read-only deploy key: the public
half on vrvrv/seQ, the private half in the secret `SEQ_DEPLOY_KEY` of this
repository (`.github/actions/seq-access`). To create it:

```bash
ssh-keygen -t ed25519 -N "" -C "serving-queue-theory CI (read seQ)" -f /tmp/seq_deploy
gh repo deploy-key add /tmp/seq_deploy.pub -R vrvrv/seQ -t "serving-queue-theory CI"
GH_TOKEN=$(gh auth token -u rebel-jinhwan) gh secret set SEQ_DEPLOY_KEY -R rebel-jinhwan/serving-queue-theory < /tmp/seq_deploy
rm /tmp/seq_deploy /tmp/seq_deploy.pub
```
